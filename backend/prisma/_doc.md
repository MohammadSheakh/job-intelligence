# Prisma ownership and commands

Job Intelligence is single-tenant. Its model fragments are under `schema/`;
`schema.prisma` is generated by the exact Ferio V2 builder. Do not edit the
combined file directly. Ferio commerce models, migrations, seeds, and the separate
platform database are not part of this backend.

Run from `backend/`:

| Command | Behavior |
| --- | --- |
| `pnpm prisma:schema:build` | Recursively rebuild the application schema with V2. |
| `pnpm prisma:generate` | Generate the application client from the combined schema. |
| `pnpm prisma:sync` | Build fragments, then generate; use after editing models. |
| `pnpm prisma:seed` | Execute the seed entry point, which deliberately fails without writes. |
| `pnpm prisma:migrate:dev` | Build the schema, then invoke Prisma development migrations. |
| `pnpm prisma:migrate:status` | Inspect migration status for the configured database. |
| `pnpm prisma:migrate:deploy` | Apply reviewed pending migrations to the configured database. |

`prisma.config.ts` supplies the datasource URL, migration directory, and Prisma 7
seed command. `prisma:generate` no longer rebuilds fragments implicitly; use
`prisma:sync` for that combined workflow. There is no `platform.prisma` client.

Neon already contains authoritative data. No replacement seed dataset has been
approved, and running the seed script must never silently report success. Both
`pnpm prisma:seed` and `pnpm exec prisma db seed` execute the same refusal.

The existing database has not been baselined into Prisma Migrate. Do not run
migration mutations on Neon until a reviewed baseline preserves existing tables,
indexes, and database check constraints. Development migrations can request a
reset; use them only on an intentionally disposable development database after
baseline setup. Merely adding package scripts does not establish migration parity.

Verification of this tooling used schema build, generation, validation, seed
refusal, migration CLI help, lint, typecheck, and build. No migration was applied
and no live database connection was used for verification.
